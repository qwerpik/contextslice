# D3 Seed Signals (FTS5 + S1/S4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Seed-stage signals S1 (exact symbol-name) and S4 (BM25 over symbol names) running against a per-selection in-memory FTS5 table, with deterministic output.

**Architecture:** New `seed` module in `cs-select` owns the FTS5 table lifecycle (build from snapshot symbols at selection start, dropped with the struct) plus two pure scoring functions. S1 classifies exact vs case-folded matches in Rust over FTS phrase-query candidates; S4 consumes `-bm25()` through the `b/(b+3)` normalization. No persistence, no writers, no new crates beyond re-added `rusqlite`.

**Tech Stack:** Rust 1.90, rusqlite (bundled, FTS5 enabled), existing `task`/`tuning` modules.

**Spec:** `docs/adr/ADR-023-cs-select-v1-contract-freeze.md` (D3, D6), `docs/ALGORITHM.md` §5 (S1/S4 rows), `crates/cs-select/src/task.rs`, `crates/cs-select/src/tuning.rs`.

### Task 2: FTS5 table build + S1 exact/folded scoring

**Files:**
- Modify: `crates/cs-select/src/seed.rs`
- Test: same file `#[cfg(test)] mod tests`

**Interfaces:**
- Consumes: `SeedIndex::build`, `SelectionSnapshot`, `tuning::{S1_EXACT_SYMBOL_WEIGHT, S1_CASE_SENSITIVE_VALUE, S1_CASE_INSENSITIVE_VALUE}`.
- Produces: `impl SeedIndex { pub fn seed_s1(&self, terms: &[ParsedTerm]) -> Vec<SeedScore> }` — one entry per (symbol row, matched term): exact (`name == term.original` case-sensitive... precisely: row name equals the term's lowercased key with original case equal) scores `3.0 × 1.0`; case-folded (`name.to_lowercase() == term.lower`, not exact) scores `3.0 × 0.7`. Sorted by `(score desc, path asc, symbol asc)` — deterministic. Returns `Vec`, never fails (pure read over built table).

Design note (locked): FTS5 table `CREATE VIRTUAL TABLE seed_fts USING fts5(name, file, kind, tokenize='unicode61')`, one row per snapshot symbol. S1 issues a phrase query per distinct term lower (`"term"`) for candidates, then classifies exact vs folded in Rust by string comparison. Candidate retrieval via FTS satisfies "S1 runs against FTS5" (ADR-023 D3); exactness is decided by `==`, not by the tokenizer.

### Task 3: S4 BM25 scoring + sign pin

**Files:**
- Modify: `crates/cs-select/src/seed.rs` (`SeedSignal::S4Bm25` variant + `SeedIndex::seed_s4`)

**Interfaces:**
- Consumes: FTS table from Task 2, `tuning::{S4_BM25_WEIGHT, S4_BM25_NORM_DIVISOR}`.
- Produces: `pub fn seed_s4(&self, terms: &[ParsedTerm]) -> Vec<SeedScore>` — per matched (row, term): value `b/(b+3)` where `b = -bm25(seed_fts)` (negation FIRST — FTS5 returns negative), score `1.0 × value`. Same `(score desc, path asc)` deterministic order. `SeedSignal::S4Bm25` documented as "S4 BM25 match: value b/(b+3), weight 1.0".
